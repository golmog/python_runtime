# Python Runtime

FF 플러그인이 별도의 Python과 가상 환경을 사용할 수 있도록 하는 공용 플러그인입니다. FF 기본 Python을 유지하면서 플러그인별로 패키지를 설치하고 작업을 실행합니다.

특정 서비스의 CLI나 인증 기능은 사용하는 개별 플러그인에서 관리합니다.

## 시작하기

1. FF의 플러그인 폴더에 설치합니다. 일반적인 설치 경로는 `/data/plugins/python_runtime`입니다.
2. FF를 재시작해 **Python Runtime** 메뉴를 불러옵니다.
3. **런타임 → 설정**에서 기본 Python과 가상 환경 저장 경로를 확인합니다.
4. **런타임 → 가상 환경**에서 플러그인 이름과 환경 이름을 입력하고 환경을 생성합니다.
5. 필요한 패키지를 설치하고 **실행 확인**으로 해당 환경의 Python이 실행되는지 확인합니다.

사용할 Python(예: 3.14)과 uv를 먼저 준비하고 설정에 실행 파일 경로를 지정하세요. 플러그인 소스 자체는 Python이나 uv를 자동 설치하지 않습니다.

## 설정

| 설정 | 설명 |
| --- | --- |
| 기본 Python | 새 환경에 사용할 Python입니다. 기존 환경의 버전은 바뀌지 않습니다. |
| 가상 환경 기본 저장 경로 | 기본값은 `/data/python_runtime/envs`입니다. 하위에 `플러그인 이름/환경 이름`으로 생성합니다. |
| 작업 제한 시간 | 작업 실행의 기본 제한 시간입니다. 기본값은 300초입니다. |
| 환경 생성·패키지 설치 제한 시간 | 환경 생성과 패키지 설치에 적용합니다. 기본값은 900초입니다. |
| uv 실행 파일 | 패키지 설치에 사용할 uv의 절대 경로입니다. 고급 설정에서 변경합니다. |

경로는 **컨테이너 내부 절대 경로**로 입력합니다. 저장 경로 변경은 새 환경부터 적용되며 기존 환경을 이동하지 않습니다. Docker 컨테이너를 다시 만들 때에도 유지할 수 있도록 영속 볼륨 아래 경로를 사용하세요.

설정 화면의 **Python 추가 등록**에서 별도로 설치한 Python 실행 파일을 등록할 수 있습니다. 가상 환경 안의 Python이 아닌 기본 Python 실행 파일을 지정합니다. 등록 후 버전 선택 목록에 나타납니다.

## 가상 환경

- **플러그인 이름:** 사용하는 플러그인의 패키지 이름입니다. 예: `my_plugin`.
- **환경 이름:** 기본값은 `default`입니다. 한 플러그인이 여러 환경을 사용할 수 있습니다.
- **Python:** 환경 생성에 사용할 버전을 선택합니다.
- **환경별 경로:** 비우면 기본 저장 경로를 사용합니다. 입력하면 해당 절대 경로에 생성합니다.

이름은 영문·숫자로 시작하며 영문·숫자·점·밑줄·하이픈으로 구성된 1~64자입니다. 기존 디렉터리는 덮어쓰거나 자동 등록하지 않습니다.

환경 생성은 백그라운드에서 진행합니다. 목록의 **실행 확인**은 환경의 Python 버전과 실행 경로를 보여줍니다. 다른 Python 버전이나 경로로 변경하려면 새 이름으로 환경을 만드세요.

## 패키지 조회·설치

패키지 기능은 **가상 환경** 페이지에 있습니다.

**설치 패키지**에서는 FF 기본 Python, 등록된 Python 또는 관리 중인 가상 환경을 선택해 패키지 이름과 버전을 조회합니다. 최초 선택은 Python 3.14이며, 이후 조회 대상을 변경하면 현재 페이지에서는 선택을 유지합니다. 패키지 이름으로 검색할 수 있습니다.

**패키지 설치**에서는 설치할 가상 환경을 선택하고 패키지를 한 줄에 하나씩 입력합니다.

```text
requests==2.32.5
pydantic>=2,<3
```

패키지 이름, 버전 조건, extras를 지정할 수 있습니다. 빈 줄과 `#`으로 시작하는 주석 줄은 무시하며 최대 100개까지 입력할 수 있습니다. pip 명령이나 `--upgrade` 같은 옵션은 입력하지 않습니다.

설치는 백그라운드에서 실행하고 완료 후 패키지 목록을 갱신합니다. FF 기본 Python이나 등록된 기본 Python에는 이 화면에서 패키지를 설치하지 않습니다. 공용 플러그인은 특정 서비스의 패키지를 기본 의존성으로 설치하지 않습니다.

## 개별 플러그인 연동

FF의 app context에서 런타임 매니저를 가져옵니다. 긴 작업은 FF의 백그라운드 작업에서 실행하세요.

```python
from python_runtime import get_runtime

runtime = get_runtime()
runtime.ensure_environment('my_plugin')
runtime.install_packages('my_plugin', ['requests==2.32.5'])

result = runtime.run_python(
    'my_plugin',
    ['/data/workers/job.py'],
    input='{"job_id": 42}',
    timeout=120,
)
print(result['returncode'], result['stdout'], result['stderr'])
```

설치할 패키지와 설치 시점은 개별 플러그인이 결정합니다. 위 설치 호출을 매 작업마다 실행할 필요는 없습니다. 작업자 코드는 지정한 경로에 별도로 두거나 가상 환경에 패키지로 설치해야 합니다.

| 공용 API | 역할 |
| --- | --- |
| `ensure_environment(owner, name='default', python=None, path=None)` | 환경을 생성하거나 기존 등록 환경 정보를 반환합니다. `python`과 `path`는 키워드 인자입니다. |
| `install_packages(owner, packages, name='default')` | 지정 환경에 패키지를 설치합니다. |
| `run_python(owner, args, name='default', ...)` | 환경의 Python으로 스크립트나 코드를 실행합니다. |
| `run_module(owner, module, args=(), name='default', ...)` | `python -m` 방식으로 모듈을 실행합니다. |
| `run_executable(owner, executable, args=(), name='default', ...)` | 환경의 `bin`에 설치된 CLI를 실행합니다. |

실행 API는 `timeout`, `input`, `cwd`, `env`를 키워드 인자로 받습니다. 결과는 `returncode`, `stdout`, `stderr`를 포함한 사전입니다. 실행한 프로그램이 실패한 경우 호출한 플러그인이 `returncode`를 확인해야 합니다. 제한 시간 초과나 실행 자체가 불가능한 경우 `python_runtime.RuntimeError`가 발생합니다.

FF의 UI·로그인·설정·DB 객체는 기존 Python에서 처리하고, 새 Python 작업자와는 JSON 등으로 필요한 값만 주고받습니다. FF 객체를 작업자로 직접 전달할 수는 없습니다. 외부 서비스 인증도 개별 플러그인이 연결합니다.

## 현재 범위

- Python 버전은 별도로 설치한 뒤 등록합니다. 자동 업데이트는 제공하지 않습니다.
- 기존 환경의 자동 이동·삭제나 패키지 자동 업그레이드는 제공하지 않습니다.
- 표준 출력과 오류는 메모리에 모아 반환하므로 큰 결과는 파일로 저장하고 경로를 전달하세요.
- 플러그인 이름은 환경을 구분하는 기준입니다. 가상 환경은 패키지·프로세스 분리 기능이며 보안 샌드박스가 아닙니다.

## 동작 확인

1. **런타임 → 설정**에서 등록된 Python 버전과 실행 파일 경로를 확인합니다.
2. **런타임 → 가상 환경**에서 환경을 하나 만들고 **실행 확인**을 누릅니다.
3. 선택한 버전과 가상 환경 내부의 Python 실행 경로가 표시되는지 확인합니다.
4. 필요한 패키지를 설치한 뒤 해당 환경의 **설치 패키지** 목록에서 이름과 버전을 확인합니다.
